01

¿Qué es el diseño responsive?

El diseño web responsive (RWD, Responsive Web Design) es un enfoque de diseño y desarrollo que hace que las páginas web se vean y funcionen bien en cualquier dispositivo y tamaño de pantalla, sin necesidad de versiones separadas del sitio.

Fue introducido por Ethan Marcotte en 2010 y se basa en tres pilares técnicos fundamentales:

Pilar 1
⬡

Rejillas fluidas

Layouts basados en porcentajes (%) en lugar de píxeles fijos.

Pilar 2
◫

Imágenes flexibles

Imágenes que se escalan dentro de su contenedor sin desbordarse.

Pilar 3
◈

Media Queries

CSS condicional que aplica estilos según las características del dispositivo.

Por qué importa

Más del 60% del tráfico web mundial llega desde dispositivos móviles. Google usa el índice Mobile-First: rastrea y posiciona las páginas basándose en su versión móvil. Un diseño no-responsive penaliza tanto la experiencia como el SEO.

02

Viewport y el meta tag esencial

El viewport es el área visible de la página en el navegador. Sin el meta tag correcto, los móviles simulan una pantalla de escritorio y hacen zoom out, rompiendo cualquier diseño responsive.

HTML
<!-- Obligatorio en el <head> de todo proyecto responsive -->
<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

<!-- Opciones del atributo content -->
<!-- width=device-width    → ancho del viewport = ancho del dispositivo -->
<!-- initial-scale=1.0    → sin zoom inicial -->
<!-- maximum-scale=1.0    → deshabilita zoom del usuario (NO recomendado) -->
<!-- user-scalable=no     → deshabilita zoom (MALO para accesibilidad) -->
✓ Con meta viewport
<!-- El navegador usa el ancho
real del dispositivo -->
<meta name="viewport"
  content="width=device-width,
           initial-scale=1.0">
<!-- ✅ Layout funciona -->
<!-- ✅ Media queries actúan -->
✗ Sin meta viewport
<!-- El móvil simula 980px
de ancho y hace zoom out -->

<!-- ❌ Texto diminuto -->
<!-- ❌ Media queries no
    se activan correctamente -->
<!-- ❌ Usuario debe hacer zoom -->
CSS
/* CSS también tiene acceso al viewport */
.hero {
  width:      100vw;     /* 100% del ancho del viewport */
  height:     100vh;     /* 100% del alto del viewport */
  min-height: 100svh;   /* Small Viewport Height — evita bug en móviles */
  min-height: 100dvh;   /* Dynamic Viewport Height — recomendado */
}

/* Unidades lógicas de viewport */
/* vw — viewport width,   1vw = 1% del ancho   */
/* vh — viewport height,  1vh = 1% del alto    */
/* vmin — el menor entre vw y vh                */
/* vmax — el mayor entre vw y vh                */
/* svh/lvh/dvh — variantes para barras de UI    */
El bug del 100vh en iOS

En iOS Safari, 100vh incluye la barra del navegador aunque esté visible, causando un desplazamiento. Usa 100svh (small viewport height) o 100dvh (dynamic viewport height) para secciones a pantalla completa en móvil.

03

Unidades relativas

Las unidades relativas son la base del diseño responsive. A diferencia de px (absoluto), se adaptan al contexto donde se usan.

UnidadRelativa aCuándo usarEjemplo
remfont-size del elemento raíz (<html>, default 16px)Tipografía, espaciados globales1rem = 16px, 1.5rem = 24px
emfont-size del elemento padrePadding/margin relativo al componenteSi padre=20px, 1em=20px
%Dimensión del elemento padreAnchos fluidos, imágeneswidth: 50% = mitad del padre
vwAncho del viewportSecciones full-width, tipografía fluida1vw = 1% del viewport
vhAlto del viewportSecciones hero, sticky elements100vh = pantalla completa
frEspacio disponible en gridColumnas de CSS Grid1fr = 1 fracción del espacio
chAncho del carácter "0"Ancho máximo de textos legiblesmax-width: 65ch
clamp()Función: min, ideal, maxTipografía y espaciados fluidosclamp(1rem, 2.5vw, 2rem)
CSS
/* ——— rem: tipografía escalable ——— */
html  { font-size: 16px; }    /* base */
h1    { font-size: 2.5rem; }  /* 40px */
p     { font-size: 1rem; }    /* 16px */
small { font-size: 0.875rem; } /* 14px */

/* Si el usuario cambia el tamaño de fuente del navegador a 20px,
   TODOS los rem se escalan proporcionalmente. ¡Accesibilidad gratis! */

/* ——— % para layouts fluidos ——— */
.contenedor {
  width:     90%;        /* 90% del viewport */
  max-width: 1200px;    /* límite máximo */
  margin:    0 auto;     /* centrar */
  padding:   0 5%;       /* padding relativo */
}

/* ——— clamp(): el valor fluido perfecto ——— */
/* Sintaxis: clamp(mínimo, ideal, máximo) */

h1 {
  font-size: clamp(1.75rem, 4vw, 3rem);
  /* Mínimo: 28px | Crece con 4vw | Máximo: 48px */
  /* En 700px viewport: 4vw = 28px → 1.75rem
     En 1200px viewport: 4vw = 48px → 3rem (tope)   */
}

.seccion {
  padding: clamp(2rem, 5vw, 6rem);
  /* Espaciado fluido sin media queries */
}

/* ——— ch para ancho de columna de texto ——— */
.articulo p {
  max-width: 65ch;       /* ~65 caracteres = longitud óptima de lectura */
}

/* ——— min() y max() ——— */
.elemento {
  width:    min(400px, 90%); /* el menor: 400px fijo o 90% del padre */
  padding: max(1rem, 2vw);  /* el mayor: al menos 1rem */
}

04

Media Queries

Las media queries son la herramienta central del diseño responsive. Permiten aplicar bloques de CSS condicionalmente según las características del dispositivo o entorno.

CSS
/* Sintaxis básica */
@media (condición) {
  /* CSS que aplica cuando se cumple */
}

/* ——— Por ancho de pantalla (más común) ——— */
@media (min-width: 768px) { ... }   /* pantallas ≥ 768px */
@media (max-width: 767px) { ... }   /* pantallas < 768px */

/* ——— Rangos exactos ——— */
@media (min-width: 768px) and (max-width: 1023px) { /* tablets */ }

/* ——— Sintaxis moderna (range) — más legible ——— */
@media (768px <= width < 1024px) { /* tablets — nueva sintaxis */ }
@media (width >= 1024px)           { /* desktop y más */ }

/* ——— Orientación ——— */
@media (orientation: portrait)  { /* vertical */ }
@media (orientation: landscape) { /* horizontal */ }

/* ——— Tipo de medio ——— */
@media screen  { /* pantallas */ }
@media print   { /* impresión */ }

/* ——— Preferencias del usuario ——— */
@media (prefers-color-scheme: dark)    { /* modo oscuro */ }
@media (prefers-reduced-motion: reduce) { /* sin animaciones */ }
@media (prefers-contrast: more)         { /* contraste alto */ }

/* ——— Pantalla de alta resolución ——— */
@media (min-resolution: 2dppx)         { /* retina/HiDPI */ }

/* ——— Combinar condiciones ——— */
@media screen and (min-width: 768px) { }
@media (min-width: 768px) or (orientation: landscape) { }

Media queries en práctica

CSS
/* Modo oscuro automático con variables */
:root {
  --bg:   #FFFFFF;
  --text: #1C1917;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg:   #1C1917;
    --text: #F5F4F0;
  }
}

/* Eliminar hover en dispositivos táctiles */
@media (hover: hover) {
  .boton:hover {
    background: var(--color-hover);
  }
}

/* Ocultar animaciones para usuarios que lo prefieren */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration:   0.01ms !important;
    transition-duration:  0.01ms !important;
    scroll-behavior:      auto   !important;
  }
}

/* Estilos de impresión */
@media print {
  .sidebar, .nav, .footer, .ads { display: none; }
  body    { font-size: 12pt; color: #000; }
  a::after { content: " (" attr(href) ")"; } /* mostrar URLs */
}

Breakpoints

Los breakpoints son los puntos de quiebre donde el diseño cambia para adaptarse a diferentes tamaños. No existe un estándar único, pero hay convenciones ampliamente aceptadas.

CSS
/* ✅ Sistema de breakpoints con variables */
:root {
  --bp-sm: 640px;
  --bp-md: 768px;
  --bp-lg: 1024px;
  --bp-xl: 1280px;
}

/* Enfoque mobile-first (min-width) */
.galeria {
  display: grid;
  grid-template-columns: 1fr;            /* 1 col — base móvil */
  gap: 16px;
}

@media (min-width: 640px)  { .galeria { grid-template-columns: repeat(2, 1fr); } }
@media (min-width: 1024px) { .galeria { grid-template-columns: repeat(3, 1fr); } }
@media (min-width: 1280px) { .galeria { grid-template-columns: repeat(4, 1fr); } }

/* ⚠️ Elige breakpoints basándote en TU CONTENIDO, no en dispositivos.
   Si el diseño se "rompe" a 730px, pon un breakpoint en 730px. */
El consejo de los profesionales

Los mejores breakpoints son los que emergen del contenido, no los que coinciden con modelos de dispositivos específicos. Un iPhone 14 tiene un ancho diferente al iPhone 15. Diseña para el contenido, no para el dispositivo.

06

Enfoque Mobile-First

Mobile-First es una estrategia de diseño y desarrollo donde se empieza por la experiencia en pantallas pequeñas y se añade complejidad para pantallas mayores. Es el enfoque recomendado en la industria.

✓ Mobile-First (min-width)
/* Base: móvil */
.grid {
  display: grid;
  grid-template-columns: 1fr;
}

/* Tablet */
@media (min-width: 768px) {
  .grid {
    grid-template-columns:
      repeat(2, 1fr);
  }
}

/* Desktop */
@media (min-width: 1024px) {
  .grid {
    grid-template-columns:
      repeat(3, 1fr);
  }
}
✗ Desktop-First (max-width)
/* Base: desktop — malo */
.grid {
  display: grid;
  grid-template-columns:
    repeat(3, 1fr);
}

/* Tablet */
@media (max-width: 1023px) {
  .grid {
    grid-template-columns:
      repeat(2, 1fr);
  }
}

/* Móvil — sobreescribiendo todo */
@media (max-width: 767px) {
  .grid {
    grid-template-columns: 1fr;
  }
}

Por qué Mobile-First es mejor

📱 Rendimiento
Los móviles descargan solo el CSS base; los desktops descargan más pero tienen más capacidad.
🔍 SEO
Google usa Mobile-First indexing: el contenido móvil es el que posiciona.
✍️ Simplicidad
Es más fácil añadir complejidad que quitarla. Empieza simple.
♿ Accesibilidad
Las restricciones del móvil fuerzan diseños más claros y accesibles.
🌍 Alcance
En muchos países, el móvil es el único dispositivo de acceso a internet.
⚡ Especificidad
Con min-width, el CSS se acumula limpiamente; con max-width se sobreescribe.

Flexbox responsive

Flexbox tiene propiedades intrínsecamente responsivas que pueden eliminar la necesidad de media queries en muchos casos.

CSS
/* ——— flex-wrap: el aliado del responsive ——— */
.tarjetas {
  display:   flex;
  flex-wrap: wrap;         /* permite salto de línea */
  gap:       16px;
}

.tarjeta {
  flex: 1 1 280px;          /* grow shrink basis */
  /* Crece y se encoge, base de 280px.
     En 600px: 2 tarjetas. En 400px: 1 tarjeta.
     ¡Sin media queries! */
}

/* ——— Patrón: stack en móvil, fila en desktop ——— */
.grupo {
  display:        flex;
  flex-direction: column;    /* columna en móvil */
  gap:            16px;
}

@media (min-width: 768px) {
  .grupo {
    flex-direction: row;       /* fila en tablet/desktop */
    align-items:    center;
  }
}

/* ——— flex-grow para llenar espacio disponible ——— */
.barra-busqueda {
  display:     flex;
  gap:         8px;
}

.barra-busqueda input  { flex: 1; }       /* ocupa todo el espacio */
.barra-busqueda button { flex-shrink: 0; } /* no se encoge */

/* ——— Reordenar elementos en móvil ——— */
.layout   { display: flex; flex-direction: column; }
.sidebar  { order: 2; } /* sidebar va después del contenido en móvil */
.contenido { order: 1; } /* contenido principal primero */

@media (min-width: 1024px) {
  .layout   { flex-direction: row; }
  .sidebar  { order: 1; width: 280px; flex-shrink: 0; }
  .contenido { order: 2; flex: 1; }
}
08

CSS Grid responsive

CSS Grid tiene funciones específicamente diseñadas para layouts responsivos, muchas de las cuales no requieren ninguna media query.

CSS
/* ——— auto-fit + minmax: el combo más poderoso ——— */
.galeria {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 20px;
  /* ✨ Sin media queries:
     En 400px  → 1 columna (220px mínimo)
     En 700px  → 2 columnas
     En 900px  → 3 columnas
     En 1200px → 4 columnas  */
}

/* ——— auto-fill vs auto-fit ——— */
.con-fill {
  grid-template-columns: repeat(auto-fill, minmax(150px, 1fr));
  /* auto-fill: mantiene columnas vacías (espacio vacío) */
}

.con-fit {
  grid-template-columns: repeat(auto-fit, minmax(150px, 1fr));
  /* auto-fit: colapsa columnas vacías (elementos se expanden) */
}

/* ——— Layout de página con grid-template-areas ——— */
.pagina {
  display: grid;
  min-height: 100vh;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header"
    "main"
    "footer";
}

@media (min-width: 1024px) {
  .pagina {
    grid-template-columns: 280px 1fr;
    grid-template-areas:
      "header  header"
      "sidebar main"
      "footer  footer";
  }
  .sidebar { grid-area: sidebar; display: block; }
}

header { grid-area: header; }
main   { grid-area: main; }
footer { grid-area: footer; }
.sidebar { display: none; } /* oculto en móvil */

/* ——— Elemento que ocupa más columnas en desktop ——— */
.featured {
  grid-column: 1 / -1;  /* siempre ocupa todo el ancho */
}

@media (min-width: 768px) {
  .featured {
    grid-column: span 2;  /* 2 columnas en tablet */
  }
}
09

Container Queries

Las Container Queries (2023) son una revolución en el diseño responsive: en lugar de responder al tamaño de la ventana, los componentes responden al tamaño de su contenedor padre. Esto permite componentes verdaderamente reutilizables.

CSS
/* ——— Paso 1: definir el contenedor ——— */
.tarjeta-wrapper {
  container-type: inline-size;  /* monitorear ancho */
  container-name: tarjeta;        /* nombre opcional */
  /* Shorthand: container: tarjeta / inline-size; */
}

/* ——— Paso 2: usar @container en lugar de @media ——— */
.tarjeta {
  display: flex;
  flex-direction: column;
  padding: 16px;
}

@container tarjeta (min-width: 400px) {
  .tarjeta {
    flex-direction: row;  /* horizontal si el contenedor es amplio */
    align-items:    center;
  }
  .tarjeta__imagen {
    width: 40%;
    flex-shrink: 0;
  }
}

/* ——— Unidades de contenedor ——— */
.tarjeta h2 {
  font-size: clamp(1rem, 5cqi, 1.5rem);
  /* cqi = container query inline, como vw pero del contenedor */
}

/* Unidades de container:
   cqw  — 1% del ancho del contenedor
   cqh  — 1% del alto del contenedor
   cqi  — 1% del inline-size del contenedor
   cqb  — 1% del block-size del contenedor
   cqmin / cqmax — menor / mayor entre cqi y cqb */

/* ——— Ejemplo real: componente de producto ——— */
.producto-wrapper { container-type: inline-size; }

.producto { display: grid; gap: 12px; }

@container (min-width: 300px) {
  .producto { grid-template-columns: 120px 1fr; }
}

@container (min-width: 480px) {
  .producto__precio  { font-size: 1.4rem; }
  .producto__boton   { display: flex; }
}
Cuándo usar Container vs Media Queries

Usa media queries para cambios globales de layout (columnas de página, navbar). Usa container queries para componentes que se reutilizan en contextos con diferentes anchos (tarjetas en sidebar vs. en main, artículos en grid de 2 o 4 columnas).

Tipografía fluida

La tipografía fluida se escala suavemente entre un tamaño mínimo y máximo sin saltos bruscos, usando clamp() o propiedades modernas.

CSS
/* ——— Sistema tipográfico fluido ——— */
:root {
  /* Fórmula: clamp(min, preferida, max) */
  --text-xs:   clamp(0.75rem,  1.5vw,  0.875rem); /* 12–14px */
  --text-sm:   clamp(0.875rem, 1.8vw,  1rem);    /* 14–16px */
  --text-base: clamp(1rem,     2vw,    1.125rem); /* 16–18px */
  --text-lg:   clamp(1.125rem, 2.5vw,  1.375rem); /* 18–22px */
  --text-xl:   clamp(1.25rem,  3vw,    1.75rem);  /* 20–28px */
  --text-2xl:  clamp(1.5rem,   3.5vw,  2.25rem);  /* 24–36px */
  --text-3xl:  clamp(1.875rem, 4.5vw,  3rem);    /* 30–48px */
  --text-4xl:  clamp(2.25rem,  5.5vw,  4rem);    /* 36–64px */

  /* Espaciados fluidos */
  --space-sm:  clamp(0.75rem, 2vw,  1rem);
  --space-md:  clamp(1rem,    3vw,  1.5rem);
  --space-lg:  clamp(1.5rem,  5vw,  3rem);
  --space-xl:  clamp(2rem,    8vw,  5rem);
  --space-2xl: clamp(3rem,    10vw, 8rem);
}

/* Aplicación */
body  { font-size: var(--text-base); }
h1    { font-size: var(--text-4xl); }
h2    { font-size: var(--text-3xl); }
h3    { font-size: var(--text-2xl); }

.hero { padding: var(--space-2xl) var(--space-lg); }

/* ——— Longitud óptima de lectura ——— */
.articulo {
  max-width:   65ch;     /* ~65 caracteres: óptimo para lectura */
  margin:      0 auto;
  line-height: 1.7;      /* 1.5–1.8 para cuerpo de texto */
}

/* ——— font-size base responsive en :root ——— */
html {
  font-size: clamp(14px, 1.5vw, 18px);
  /* Todos los rem se escalan automáticamente */
}

Imágenes responsivas

Las imágenes son el recurso más pesado de una página web. Servirlas correctamente en cada dispositivo es crucial para el rendimiento y la experiencia visual.

CSS + HTML
/* ——— La regla CSS más importante ——— */
img, video, iframe {
  max-width: 100%;   /* nunca desborda el contenedor */
  height:    auto;   /* mantiene la proporción */
  display:   block;  /* evita el espacio en línea */
}

/* ——— Aspect-ratio para reservar espacio ——— */
.imagen-hero  { aspect-ratio: 16/9; width: 100%; object-fit: cover; }
.avatar        { aspect-ratio: 1/1;  width: 60px; object-fit: cover; border-radius: 50%; }
.tarjeta-thumb { aspect-ratio: 4/3;  width: 100%; object-fit: cover; }
HTML
<!-- ——— srcset: diferentes tamaños de imagen ——— -->
<img
  src="imagen-800.jpg"            <!-- fallback -->
  srcset="imagen-400.jpg  400w,
          imagen-800.jpg  800w,
          imagen-1200.jpg 1200w,
          imagen-2400.jpg 2400w"
  sizes="(max-width: 640px)  100vw,
         (max-width: 1024px) 50vw,
         33vw"
  alt="Descripción"
  loading="lazy"
  decoding="async"
  width="800" height="450"         <!-- evita CLS -->
>

<!-- ——— <picture>: art direction y formatos modernos ——— -->
<picture>
  <!-- Formato moderno (AVIF) -->
  <source type="image/avif"
          srcset="img.avif 1x, img@2x.avif 2x">

  <!-- WebP para navegadores compatibles -->
  <source type="image/webp"
          srcset="img.webp 1x, img@2x.webp 2x">

  <!-- Imagen diferente para móvil (art direction) -->
  <source media="(max-width: 640px)"
          srcset="img-vertical.jpg">

  <!-- Fallback JPG -->
  <img src="img.jpg" alt="Descripción"
       loading="lazy" width="800" height="600">
</picture>

<!-- ——— Imagen de fondo responsiva ——— -->
<style>
.hero {
  background-image: url('hero-sm.jpg');    /* móvil: imagen pequeña */
  background-size: cover;
  background-position: center;
}

@media (min-width: 768px) {
  .hero { background-image: url('hero-md.jpg'); }
}

@media (min-width: 1280px) {
  .hero { background-image: url('hero-lg.jpg'); }
}
</style>

Navbar responsive

La navegación es uno de los elementos más complejos de hacer responsive. El patrón más común convierte el menú horizontal en un menú hamburguesa en móvil.

<header>
  <nav class="navbar" aria-label="Navegación principal">

    <a href="/" class="navbar__logo">MiSitio</a>

    <!-- Botón hamburguesa (solo móvil) -->
    <button
      class="navbar__toggle"
      aria-label="Abrir menú"
      aria-expanded="false"
      aria-controls="nav-menu"
    >
      <span></span>
      <span></span>

Accesibilidad en diseño responsive

El diseño responsive y la accesibilidad van de la mano. Un sitio verdaderamente responsivo funciona para todos los usuarios: personas con discapacidades visuales, motoras, cognitivas, y quienes usan tecnologías asistivas.

CSS
/* ——— 1. Tamaños táctiles mínimos ——— */
button, a, input, select, textarea {
  min-height: 44px;   /* WCAG recomienda 44×44px para áreas táctiles */
  min-width:  44px;
}

/* ——— 2. Nunca eliminar el foco — personalízalo ——— */
:focus-visible {
  outline:        2px solid #FF5C3A;
  outline-offset: 2px;
  border-radius:  3px;
}

/* ——— 3. Contraste de colores (WCAG AA: 4.5:1 para texto) ——— */
.texto-cuerpo { color: #1C1917; }    /* 16:1 sobre blanco ✅ */
.texto-muted  { color: #595550; }    /* 7:1 sobre blanco  ✅ */
/* EVITAR: #999 sobre #fff → relación 2.85:1 ❌ */

/* ——— 4. Tamaño de fuente mínimo legible ——— */
body { font-size: clamp(1rem, 2vw, 1.125rem); }
/* Nunca menos de 16px para texto de cuerpo */

/* ——— 5. Usar rem (no px) para que escale con el usuario ——— */
h1 { font-size: 2rem; }    /* ✅ escala si el usuario cambió la fuente base */
h1 { font-size: 32px; }   /* ❌ fijo aunque el usuario quiera más grande */

/* ——— 6. Animaciones opcionales ——— */
@media (prefers-reduced-motion: no-preference) {
  .animado { transition: transform .3s ease; }
}

/* ——— 7. Zoom del usuario ——— */
meta [name="viewport"] {
  /* ✅ correcto */
  content: "width=device-width, initial-scale=1";
  /* ❌ NUNCA deshabilitar zoom */
  /* content: "...user-scalable=no"  ← viola WCAG 1.4.4 */
}

/* ——— 8. Texto alternativo para imágenes de fondo ——— */
.foto-perfil {
  background-image: url('foto.jpg');
  /* ⚠️ Las imágenes de fondo no son accesibles para lectores de pantalla.
     Usa <img alt="..."> para imágenes de contenido. */
}

Rendimiento en sitios responsive

Un buen diseño responsive también es un diseño performante. Las métricas de Core Web Vitals de Google penalizan los sitios lentos.

HTML + CSS
<!-- ——— 1. Preload de recursos críticos ——— -->
<link rel="preload" as="font"
  href="fuente.woff2"
  type="font/woff2"
  crossorigin>

<!-- ——— 2. CSS crítico inline, resto diferido ——— -->
<style>
  /* CSS above-the-fold inline */
  body { margin: 0; font-family: sans-serif; }
</style>
<link rel="stylesheet" href="estilos.css"
      media="print" onload="this.media='all'">

<!-- ——— 3. Imágenes lazy loading ——— -->
<img src="foto.jpg" loading="lazy"
     decoding="async"
     width="800" height="450"
     alt="...">

<!-- ——— 4. Fuentes optimizadas ——— -->
<style>
@font-face {
  font-family:   'MiFuente';
  src:           url('fuente.woff2') format('woff2');
  font-display:  swap;  /* muestra texto con fuente de sistema inmediatamente */
  font-weight:   400 700; /* variable font range */
}
</style>

/* ——— 5. CSS para evitar layout shift (CLS) ——— */
img   { aspect-ratio: attr(width) / attr(height); }  /* reservar espacio */

<link rel="stylesheet" href="tablet.css"

Buenas prácticas

  • Incluye siempre <meta name="viewport" content="width=device-width, initial-scale=1.0"> en el <head>.
  • Diseña siempre Mobile-First con min-width. Empieza por el caso más restrictivo.
  • Usa clamp() para tipografía y espaciados que se escalen fluidamente sin media queries.
  • Prefiere rem sobre px para tipografía, para respetar las preferencias del usuario.
  • Añade siempre max-width: 100%; height: auto; a las imágenes para que no se desborden.
  • Especifica siempre width y height en las imágenes HTML para prevenir el Layout Shift (CLS).
  • Prueba en dispositivos reales además de en el inspector del navegador. Los dispositivos reales revelan bugs de rendimiento y táctiles.
  • Nunca deshabilites el zoom con user-scalable=no. Viola WCAG y perjudica a usuarios con baja visión.
  • Usa @media (prefers-reduced-motion: reduce) para desactivar animaciones cuando el usuario lo prefiere.
  • Establece breakpoints basados en tu contenido, no en modelos de dispositivos concretos.
  • Usa repeat(auto-fit, minmax(...)) en Grid para layouts responsivos sin media queries.
  • Verifica el contraste de colores con herramientas como WebAIM Contrast Checker. Mínimo 4.5:1 para texto normal.
